# 기술 블로그 작성 및 편집

글을 작성하거나 편집하기 전에 [라이팅 스타일](references/writing-style.md)을 읽고 적용한다.

사용자가 요청한 범위에 맞춰 작업한다. 문체 수정 요청에서는 내용과 기술적 주장을 유지하고 표현을 다듬는다.

## 이미지와 다이어그램

이미지는 저장소의 `assets/<글 식별자>/`에 저장한다. 다이어그램에는 Excalidraw를 적극 활용하고, 편집 가능한 `.excalidraw` 원본과 게시용 PNG를 함께 보관한다.

다이어그램에는 구조, 관계, 상태 변화와 흐름을 이해하는 데 필요한 이름과 짧은 표기만 넣는다. 조건, 가정, 해석, 결론, 트레이드오프 등 문장으로 풀어 쓸 부연 설명은 블로그 본문에 작성하고 그림 안에 중복하지 않는다. 배치와 연결만으로 방향을 이해할 수 있으면 `시간 →` 같은 안내 표기도 생략한다.

이미지를 본문에 넣을 때는 다음 순서를 따른다.

1. 이미지를 만들고 직접 열어 글자, 배치, 잘림과 내용의 정확성을 확인한다.
2. 사용자에게 실제 이미지 미리보기를 보여주고 확인받는다. 수정 요청이 있으면 반영한 이미지를 다시 보여준다.
3. 사용자가 확인한 이미지와 편집용 원본을 커밋하고 `origin/main`에 푸시한다. 이 이미지 게시 작업은 사용자가 요청한 워크플로에 포함된다. 관련 파일만 커밋하며 다른 변경은 포함하지 않는다.
4. 게시용 이미지의 GitHub URL에 직접 요청해 HTTP 200 응답과 이미지 콘텐츠가 반환되는지 확인한다. 404 등으로 접근할 수 없으면 원인을 해결하기 전까지 본문에 삽입하지 않는다.
5. 확인된 URL을 Markdown 이미지 문법으로 본문에 넣는다. 문서 자체의 커밋과 푸시는 별도 사용자 지시를 따른다.

URL 형식은 `https://raw.githubusercontent.com/momentjin/blog/main/assets/<글 식별자>/<이미지명>.png`를 사용한다. 로컬 절대 경로나 아직 푸시하지 않은 파일의 URL을 완성된 본문에 넣지 않는다. 완료 보고에서는 로컬 미리보기 확인과 원격 URL 확인을 구분한다.

기술 검토 기준이나 연재 구성 규칙은 필요할 때 점진적으로 추가한다.
