# 라이팅 스타일

## 인용문

Markdown 인용 블록(`>`)으로 작성하는 안내문이나 설명문은 `습니다`체를 사용한다.

예시:

> 이 시리즈는 운영 중인 시스템의 문제를 시작으로, Event Sourcing과 CQRS를 적용한 과정을 소개합니다.

외부 자료나 다른 사람의 말을 직접 인용할 때는 원문의 문체를 그대로 보존한다.

## 일반 본문

일반 본문은 `한다`, `했다`, `~다` 형태의 평서체를 사용한다. 독자에게 가정이나 예시를 함께 살펴보도록 제안할 때는 `해보자`, `보자` 형태를 사용한다.

- 동작이나 일반적인 사실: `이용료를 계산한다.`
- 과거의 구현이나 경험: `계산한 이용료를 함께 저장했다.`
- 상태나 판단: `현재 값을 읽는 데에는 편리한 구조다.`
- 가정이나 예시 도입: `고객이 반납을 취소했다고 해보자.`
- 함께 살펴보기: `먼저 기존 데이터 구조를 보자.`

일반 본문에 `합니다`, `했습니다`, `해요` 형태를 섞지 않는다. 문맥에 맞춰 시제와 어미를 선택하며, 모든 문장을 같은 어미로 통일하지 않는다.

## 문단과 줄바꿈

문단은 하나의 질문이나 논점을 설명하는 단위로 구성한다. 같은 주장의 근거, 예시, 원인과 결과는 한 문단에서 연결한다. 문장이 끝났다는 이유로 빈 줄을 넣거나, 강조를 위해 한 문장씩 문단을 만들지 않는다. 본문 문단 안에는 수동 줄바꿈을 넣지 않고 화면 너비에 따른 자동 줄바꿈을 사용한다.

새 문단은 다음 중 하나에 해당할 때 나눈다.

- 설명할 질문이나 중심 논점이 바뀐다.
- 하나의 설명을 마친 뒤 독립적으로 다뤄야 할 대안, 반론, 한계로 넘어간다.
- 예시가 길어져 여러 단계의 설명이 필요하다. 이 경우 예시 전체를 하나의 문단으로 묶고, 해석이나 일반화가 시작될 때 다음 문단으로 넘어간다.

`하지만`, `따라서`, `예를 들어` 같은 연결어만으로 문단을 나누지 않는다. 앞 문장의 직접적인 보충이나 짧은 예시는 같은 문단에 이어 쓴다. 문장 수나 글자 수를 고정 기준으로 삼지 않으며, 문단이 길다면 실제로 논점이 전환되는 지점을 찾아 나눈다.

편집을 마칠 때 인접 문단을 함께 읽고, 같은 질문에 답하거나 앞 문단을 바로 보충한다면 합친다. 한두 문장짜리 문단이 연속되면 분리할 이유가 있는지 다시 확인한다. 표, 코드, 다이어그램 앞뒤에는 Markdown에 필요한 빈 줄을 두되, 이를 위해 설명 문단을 불필요하게 쪼개지 않는다.

예를 들어 아래 세 문장은 대안의 동작과 효과를 함께 설명하므로 한 문단으로 작성한다.

현재 내역을 갱신하면서 이전 값과 변경 값, 처리자, 변경 사유를 이력에 저장한다. 상태 갱신과 이력 기록을 같은 DB 트랜잭션으로 묶으면 둘 중 하나만 커밋되는 문제도 막을 수 있다. 현재 값을 조회하는 방식은 유지하면서 변경 과정도 확인할 수 있다.
